# Микро-мессенджер

Electron-клиент + Node-сервер для приватного мессенджера с друзьями по
списку и сквозным (E2E) шифрованием сообщений.

## Установка из исходников

```bash
git clone https://github.com/TechMagicInfinity/DMmessenger.git
cd DMmessenger
npm install
npm start
```

Сервер разворачивается отдельно (папка `server/`):

```bash
cd server
npm install
npm start
```

По умолчанию сервер слушает `http://localhost:3000`. Порт можно поменять
переменной окружения `PORT`.

## Первый запуск

1. Вкладка **Регистрация** — сервер, ник, пароль, повтор пароля.
   Приглашение/инвайт-код больше не требуется — регистрация открыта всем,
   кто знает адрес сервера.
2. После входа список чатов **пуст** — доступа "ко всем" и общего чата
   больше нет. Чтобы начать переписку, нужно:
   - В настройках задать себе публичный **юзернейм (@)** — отдельный от
     ника при регистрации.
   - Через поиск (`@юзернейм`) найти нужного человека и отправить заявку
     в друзья.
   - Собеседник принимает заявку через колокольчик в шапке — после этого
     вы появляетесь в списках чатов друг у друга.
3. Сессия запоминается локально — при следующем запуске логиниться заново
   не нужно (кнопка "выйти" сбрасывает сессию вручную).

Если сервер сейчас выключен — увидишь "нет соединения, переподключение...";
клиент сам переподключится, как только сервер снова будет доступен.

## Сквозное (E2E) шифрование

Текст сообщений шифруется прямо на устройстве отправителя (ECDH P-256 +
HKDF + AES-256-GCM, через встроенный в Electron Web Crypto API) и
расшифровывается только на устройстве получателя. Сервер хранит и
пересылает исключительно шифротекст — даже полный доступ к его файлам не
даёт прочитать переписку.

Приватный ключ никогда не покидает устройство (хранится в `localStorage`
клиента) — значит, переписка привязана к конкретной установке приложения.
Если переустановить клиент или очистить его локальные данные, старые
сообщения станет невозможно расшифровать.

## Локальные (не синхронизируемые) фичи

Часть настроек хранится только на этом устройстве и не отправляется на
сервер: папки для сортировки чатов, личные заметки о собеседниках (видны
только тебе), выбранная тема оформления, включён ли звук/показ
уведомлений. Аватар и текст "о себе", в отличие от этого, синхронизируются
через сервер и видны друзьям. Подробности — в самом коде клиента
(`renderer.js`).

## Протокол (для тех, кто хочет написать свой клиент)

Серверу всё равно, какая программа к нему стучится. Все запросы, кроме
регистрации и логина, требуют заголовок `Authorization: Bearer <token>`.

### REST

**`POST /api/register`**
```json
{ "username": "ник", "password": "пароль (от 6 символов)" }
```

**`POST /api/login`**
```json
{ "username": "ник", "password": "пароль" }
```
Ответ: `{ "ok": true, "token": "...", "username": "..." }`. Токен живёт,
пока сервер не перезапущен (сессии не персистентны между рестартами).

**`PUT /api/handle`** — задать публичный `@юзернейм` (3–20 символов,
латиница/цифры/подчёркивание).
```json
{ "handle": "defik" }
```

**`GET /api/search?handle=defik`** — найти человека по хендлу. Ответ:
`{ "user": { username, handle, about, avatar, joinedAt, publicKey }, "status": "none" | "pending_sent" | "pending_received" | "friends" }`.

**`POST /api/friend-requests`** — отправить заявку в друзья по хендлу.
```json
{ "toHandle": "defik" }
```

**`GET /api/friend-requests`** — входящие заявки (только твои).

**`POST /api/friend-requests/:id/respond`** — принять/отклонить.
```json
{ "accept": true }
```

**`GET /api/contacts`** — список принятых друзей (уже не "все
зарегистрированные", как раньше).

**`GET /api/profiles`** — публичные профили всех юзеров (handle, about,
avatar, joinedAt, publicKey — последнее нужно для E2E-шифрования).

**`PUT /api/profile`** — обновить свой профиль (любое из полей
опционально):
```json
{ "about": "текст до 200 симв.", "avatar": "data:image/...", "publicKey": "JSON-строка JWK-ключа" }
```

### WebSocket

Подключение: `ws://адрес-сервера/ws?token=ТВОЙ_ТОКЕН`

**Отправить сообщение** (клиент → сервер) — `chat` это ник собеседника,
`text` — при включённом E2E это JSON-строка `{"v":1,"iv":"...","ct":"..."}`,
сервер её не разбирает, просто хранит и пересылает как есть:
```json
{ "type": "send", "chat": "ник_собеседника", "text": "..." }
```

**Запросить историю чата**:
```json
{ "type": "history", "chat": "ник_собеседника" }
```

**Входящее сообщение** (сервер → клиент):
```json
{ "type": "message", "chat": "ник_собеседника", "message": { "id", "from", "to", "text", "ts" } }
```

**История в ответ на запрос**:
```json
{ "type": "history", "chat": "ник_собеседника", "messages": [ /* ... */ ] }
```

**Кто сейчас онлайн** (рассылается автоматически при
подключении/отключении любого участника):
```json
{ "type": "presence", "online": ["ник1", "ник2"] }
```

**Пуш о новой заявке в друзья** (если получатель сейчас онлайн):
```json
{ "type": "friend_request", "from": { username, handle, about, avatar } }
```

**Пуш о том, что твою заявку приняли**:
```json
{ "type": "friend_accepted", "by": { username, handle, about, avatar } }
```

**Пуш об изменении чьего-то профиля** (аватар/о себе/публичный ключ):
```json
{ "type": "profile", "username", "handle", "about", "avatar", "joinedAt", "publicKey" }
```

Сервер не проверяет ничего, кроме валидности токена и базового формата
запросов — содержимое `text` (расшифровка, отображение) полностью на
совести клиента.
